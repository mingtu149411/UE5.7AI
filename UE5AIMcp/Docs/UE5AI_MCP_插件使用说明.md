# UE5 AI MCP 插件使用说明

> **项目作者水印：南京大学24届沈逸文**
> 适用版本：UE 5.7 / UE5AIMcp 0.4.0-showcase-levels ｜ 更新日期：2026-10-05

## 1. 使用前说明

UE5 AI MCP 用于让支持 MCP 的 AI 客户端在**本机**调用 Unreal Editor 的受控自动化能力。它适合辅助完成关卡检查、资产查询、场景搭建、蓝图/材质/序列创建、PIE 验证和工程诊断。

请在使用前理解以下边界：

- 插件是 **Editor** 模块，编辑器关闭时不能工作；
- 仅监听本机 `127.0.0.1:8175`，不应直接暴露到局域网或互联网；
- AI 的自然语言请求会被转换为白名单工具调用，不代表它可以无条件使用 Unreal 的任何内部 API；
- 写操作会修改项目文件。重要项目应先提交版本控制或复制备份；
- 风格、玩法、性能和商业授权仍需要人工验收。

## 2. 安装与启用

### 2.1 目录要求

当前插件目录为：

`D:\xuexishiyong\UE5AI\UE5AIMcp`

当前测试项目为：

`D:\xuexishiyong\ue--myproject\AI插件测试项目\AI插件测试项目.uproject`

测试项目在 `.uproject` 中通过 `AdditionalPluginDirectories` 指向 `D:/xuexishiyong/UE5AI`。如迁移项目，可采用其中一种方式：

1. 保持插件目录，并在 `.uproject` 的 `AdditionalPluginDirectories` 增加插件父目录；或
2. 将整个 `UE5AIMcp` 文件夹复制到 `<项目>/Plugins/UE5AIMcp`；或
3. 在 Unreal Editor 的“编辑 → 插件”中从本地目录安装/启用。

不要只复制 `.uplugin` 文件；`Source`、`Config`、`bridge` 和（必要时）`Binaries` 必须随插件目录保留。

### 2.2 首次启用

1. 启动 UE 5.7 并打开项目；
2. 在“编辑 → 插件”搜索 `UE5 AI MCP`；
3. 启用插件后按编辑器提示重启；
4. 若本机没有匹配的二进制，选择从源码编译，或先用 UE 5.7 构建插件；
5. 编辑器完全打开后，再启动 MCP 客户端或桥接程序。

成功加载后，插件会建立本地 HTTP 服务。可通过 `GET /ue5ai/health` 或 AI 客户端中的健康检查工具确认。

## 3. 配置 MCP 客户端

需要可运行 Python 的环境，并让 MCP 客户端启动本仓库中的桥接脚本。配置示例（JSON 结构，具体配置文件名取决于所用客户端）：

```json
{
  "mcpServers": {
    "ue5ai": {
      "command": "python",
      "args": [
        "D:/xuexishiyong/UE5AI/UE5AIMcp/bridge/ue5ai_mcp_bridge.py"
      ]
    }
  }
}
```

启动顺序应为：

1. 先打开目标 Unreal 项目；
2. 确认 `UE5 AI MCP` 已启用且编辑器没有停在编译/模态对话框；
3. 再启动或刷新 MCP 客户端；
4. 请求工具清单或健康检查；
5. 先做读取验证，再执行写入操作。

如果客户端显示工具连接失败，先检查 UE 是否运行、端口是否被占用、插件是否被禁用，以及 Python 路径是否可用。桥接程序不会自动启动 Unreal Editor。

## 4. 推荐工作流

### 4.1 只读勘察

在要求 AI 修改内容前，先让它读取以下信息：

1. 编辑器健康状态与工具清单；
2. 当前世界、选中 Actor、关卡和视口状态；
3. 目标目录的资产、依赖关系、蓝图/材质摘要；
4. 诊断、日志和性能快照。

推荐表述：

> 读取当前关卡与 `/Game/AI插件测试` 目录摘要；不要修改任何资源。给出可编辑目标、依赖和潜在风险。

这样可以降低 AI 在错误关卡、错误目录或未保存修改上继续操作的风险。

### 4.2 小批量写入

一次写入只处理一个明确意图，例如：创建一个材质实例、在指定目录导入三张纹理、布置一组可撤销的 Actor，或新建一个关卡序列。每次写入后要求 AI：

1. 列出创建/修改的包路径；
2. 保存脏包；
3. 回读资产或关卡状态；
4. 如有错误，先停止并说明失败原因，不要无限重试。

推荐表述：

> 在 `/Game/实验/草地` 创建一个新的材质实例；不要覆盖已有资产。保存后重新读取路径验证，返回实际资产路径和参数摘要。

### 4.3 批量任务

大型任务（例如一整个展示关卡）建议拆成“计划 → 资产 → 场景 → 交互 → 统一验证”五步，每步都有独立命名空间和保存点。不要用一个超长请求混合导入、删除、编译、PIE 和重构；这种任务很难定位失败并容易产生无用中间资产。

## 5. 常用能力与用途

| 目标 | 推荐能力 | 使用提示 |
| --- | --- | --- |
| 查看编辑器是否就绪 | 健康检查、工具清单、快照 | 这是所有自动化任务的第一步。 |
| 查看关卡与 Actor | 视口验证、属性、日志 | 先明确世界与选中对象。 |
| 创建和布置场景 | Actor 生成/变换/组织、网格布局、点光源、后处理 | 使用独立文件夹和统一命名前缀。 |
| 管理资产 | 资产导入、重导入、验证、依赖分析 | 导入后必须检查资产是否已保存。 |
| 制作材质 | 材质实例、材质图、质量预算 | 图形节点和大世界坐标必须检查类型转换。 |
| 编辑蓝图/游戏逻辑 | 蓝图创建与摘要、游戏玩法脚手架、输入映射 | 自动生成后仍建议在编辑器中人工审阅图表。 |
| 生成动画/特效/音频 | 序列、蒙太奇、Niagara、音频 Cue 工具 | 骨骼与轨道引用必须指向已有资产。 |
| 测试运行 | PIE 启动/停止、自动化发现/运行/报告 | PIE 前先保存；运行后读取运行状态。 |
| 工程治理 | 性能、合规、源控、平台、崩溃和流水线计划 | 这些能力多为分析或计划，不会替代正式 CI。 |

路由和参数会随版本演进；让 AI 先读取工具定义，而不是假定任意参数可用。

## 6. 草地演示关卡操作指南

### 6.1 打开关卡

在内容浏览器打开：

`/Game/AI插件测试/关卡二_交互草地/关卡二_全局风场草地`

或在操作系统中定位：

`D:\xuexishiyong\ue--myproject\AI插件测试项目\Content\AI插件测试\关卡二_交互草地\关卡二_全局风场草地.umap`

该关卡由地表材质、五个 HISM 草簇层、风场草材质、RT 和交互控制器组成。请不要删除以下核心资产，否则角色交互链路会失效：

- `M_二次元草簇_RT交互`
- `RT_草地交互与风场`
- `BP_第三人称RT草地交互控制器`

### 6.2 验证风与角色交互

1. 打开关卡，等待着色器编译完成；
2. 确认世界设置使用第三人称 GameMode，地图中保留 PlayerStart；
3. 在 Outliner 中确认 `BP_第三人称RT草地交互控制器` 存在；
4. 点击“播放（PIE）”，用默认第三人称角色在草地中移动；
5. 近景草会保留全局风摆动，角色周围会叠加局部压草/摆动；
6. 结束 PIE 后可读取草地状态工具，检查 `render_target_assigned`、`tracked_pawn` 和最近捕获位置。

### 6.3 可调参数

最适合试验的参数是：风方向、风幅、风速、交互半径、SceneCapture 正交宽度、RT 分辨率、HISM 密度、近中远景裁剪距离和草簇明暗配色。建议将实验参数保存为新的 Material Instance 或数据资产，而不是直接覆盖最终展示资产。

## 7. 保存、撤销与恢复

- 写入完成后使用保存脏包能力，或在 UE 中执行“保存全部”；
- 对单次场景编辑优先使用 Unreal 事务撤销/重做；
- 对批量资产修改，先创建目录级备份或提交版本控制；
- AI 请求删除 Actor/资产前，应要求它先报告精确路径和影响范围；
- 若导入资产在重启后缺失，检查其包是否真正保存，而不是只看导入调用返回成功。

本插件对二进制 `.uasset/.umap` 资产使用 Unreal API 保存；不要用文本编辑器修改这些文件，也不要让 AI 直接向二进制文件插入作者文字。

## 8. 故障排查

| 现象 | 优先检查 | 处理方式 |
| --- | --- | --- |
| MCP 没有工具或健康检查失败 | UE 编辑器、插件启用状态、端口 8175、Python 路径 | 重启编辑器并刷新 MCP 客户端；检查插件是否编译成功。 |
| 调用超时 | Unreal 是否正在编译、出现模态对话框、进入 PIE、加载大地图 | 等待编辑器空闲后重试；缩小一次操作范围。 |
| 材质为黑色/默认材质 | 输出日志、节点类型、纹理是否保存 | 先修复编译错误；检查 UV 是否为二维、贴图引用是否有效。 |
| 导入后资产消失 | Content Browser 与磁盘上的 `.uasset` | 使用保存脏包，重启后在资产注册表中验证。 |
| HISM/动态组件重开后丢失 | Actor 组件列表和地图保存状态 | 确保组件通过 `AddInstanceComponent` 持久化后保存地图。 |
| 草不与角色交互 | PIE GameMode、控制器、RT 引用和追踪 Pawn | 检查 `BP_第三人称RT草地交互控制器`、`RT_草地交互与风场` 和玩家生成。 |
| 视口截图超时 | 视口活跃度与渲染帧 | 激活编辑器视口；同时以 PIE/资产/日志状态交叉验证。 |

## 9. 安全使用建议

1. 不要将 8175 端口映射到外网；
2. 不要将源代码管理令牌、云密钥或个人凭据写入蓝图、材质、桥接脚本或提示词；
3. 对删除、重命名、批量重导入、CVar 修改、插件脚手架和 C++ 生成操作先做范围确认；
4. 每次大型自动化后执行资产验证、保存和一次人工打开检查；
5. 对商业项目保留 AI 调用记录、资产来源和人工验收记录。
