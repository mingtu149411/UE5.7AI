> **项目作者水印：南京大学24届沈逸文**

## 1. 项目概述

本项目的目标是建立一个可由 AI 助手在本地调用、同时保留 Unreal Editor 安全边界的自动化插件。实施采取“先可观测、再可操作、最后以真实内容验证”的路线：先确认 AI 能读取编辑器和项目状态，再加入受控写操作，随后用三类展示关卡验证场景、材质、蓝图、特效和交互能力。

实现位置：

- 插件：`D:\xuexishiyong\UE5AI\UE5AIMcp`
- 功能测试项目：`D:\xuexishiyong\ue--myproject\AI插件测试项目`
- UE 版本：`D:\xuexishiyong\UE\UE_5.7`

测试原则为：功能集中完成后进行批量构建与统一验证，避免每加一个小功能就进行破碎、互相干扰的单点测试；永久展示资产和关卡留在测试项目中，临时构建目录与临时截图在验证后清理。

## 3. 架构演进

初始方案仅需要让 AI 看见编辑器。实际开发很快发现，可靠自动化至少需要四层：

1. **发现层**：健康检查、工具清单、项目快照、属性、日志和资产校验；
2. **动作层**：使用显式 HTTP 路由封装 Actor、资产、材质、蓝图、关卡与 PIE 操作；
3. **调度层**：任何触及 Unreal 对象的写入都回到 Game Thread 执行；
4. **验证层**：通过资产注册表、包保存、材质编译、场景加载、PIE 运行状态与专用状态路由回读结果。

对应的 Python 桥接器仅暴露已实现的工具映射。没有设计为“把自然语言直接转为任意编辑器命令”，也不允许任意 URL 或 shell 转发；这样能保持调用范围明确并便于审查。

## 4. 展示关卡的实现记录

### 4.1 关卡一：海洋

海洋关卡从空白关卡配置天空、大气、太阳光、环境光、体积云和海面。近景采用可形变的细分平面与距离层次，远景通过贴图/材质层降低成本，海面表达以真实海面参考为目标而非复制第三方着色器源码。该关卡用于验证光照、环境、材质和大尺度场景组织。

### 4.2 关卡二：全局风场草地

早期版本已经具备“模型草、实例化布置、全局风、RT 交互”的功能链路，但视觉密度、草地与草簇的层次、卡片朝向和角色触压反馈不足。因此本轮以此关卡为重构重点，新增原创风格化草地底图与草簇纹理，强化前中远景层次，保留 HISM 与 RT 的性能方案。

最终关卡路径：

`/Game/AI插件测试/关卡二_交互草地/关卡二_全局风场草地`

永久资产包括：

- `T_二次元草地底图`
- `T_二次元草簇`
- `M_二次元草地地表`
- `M_二次元草簇_RT交互`
- `RT_草地交互与风场`
- `BP_第三人称RT草地交互控制器`

草簇采用五个 HISM 分层组件，最终保存 5,840 个实例。地表材质负责远景底色与过渡，卡片草负责近中景轮廓，避免“把地面贴图误认为草模型”的视觉混淆。

### 4.3 关卡三：二次元樱花树

樱花树关卡从基础关卡出发，建立风格化树体、花簇和 Niagara 落花表现，用于验证程序建模、材质、粒子系统与卡通风格的组合。此关卡、海洋关卡和草地关卡均作为测试项目内容保留，不在测试结束时删除。

## 5. 草地重构：问题、定位与修正

草地重构不是一次性生成后即结束，而是经历了编译、导入、保存、场景加载和 PIE 多轮验证。关键问题如下。

| 编号 | 现象 | 定位 | 修正与验证 |
| --- | --- | --- | --- |
| G-01 | 材质编译后草显示为默认黑色/无预期效果。 | 大世界坐标（LWC）输出为三分量，直接接进 RT 纹理采样器所需的二维 UV。 | 在 `RT交互二维UV` 明确提取 RG 后再采样；材质重新编译正常。 |
| G-02 | 自动导入纹理操作返回成功，但重启编辑器后不能发现资产。 | 导入工作只创建了对象，未确保资产包被标脏和保存。 | 在导入路径中标脏并调用编辑器保存，重启后确认 `.uasset` 持久存在。 |
| G-03 | 场景中可见草簇，重开地图/编辑器后实例消失。 | 动态 HISM 组件仅注册到世界，没有成为 Actor 可序列化的实例组件。 | 通过 `AddInstanceComponent` 添加后注册和保存地图；重新加载后仍存在五组 HISM、5,840 实例。 |
| G-04 | 草卡看起来像横向碎片，近景轮廓不自然。 | 平面网格姿态和竖直草簇纹理不匹配。 | 调整卡片方向（Roll 90°）并重建密度层次，获得竖直刀叶轮廓。 |
| G-05 | 交互器在 PIE 中找不到预期第三人称角色。 | 地图使用的是通用默认 Pawn 配置。 | 设置第三人称 GameMode 并放置 PlayerStart，PIE 状态回读确认已跟踪 `BP_ThirdPersonCharacter`。 |
| G-06 | 无法只用截图确认视觉结果。 | 编辑器非活动视口可能没有新渲染帧，截图路由会等待或超时。 | 使用材质编译信息、资产验证、PIE 和 `/showcase/grass/status` 联合验收；截图仅作为辅助证据。 |

### 5.1 交互实现结果

`AUE5AIStylizedGrassInteractor` 使用顶视正交 SceneCapture 在 29,000 cm 范围内写入 `RT_草地交互与风场`。蓝图 `BP_第三人称RT草地交互控制器` 在 PIE 中追踪玩家 Pawn 的 XY 坐标，交互半径约 180 cm、最高捕获频率 30 Hz。草材质从 RT 的 R 通道读取交互强度，乘以草叶根部锚定遮罩后形成局部压草，并与时间驱动的全局风场相加。

最终运行时状态确认：

```text
pie_running=true
controller=BP_第三人称RT草地交互控制器
tracked_pawn=BP_ThirdPersonCharacter
render_target_assigned=true
last_rt_capture_location=有效三维坐标
```

按项目要求，三类展示关卡、生成资产、蓝图、材质、RT 及必要的插件二进制均已保留在测试项目或插件目录中。只清理以下可再生物：

- 已被最终版本替代的短期验证缓存。

未清理 `.uasset`、`.umap`、项目配置或最终插件文件，避免影响后续人工检查和扩展开发。

## 9. 后续建议

1. 为每个高风险写入路由补充自动化回归用例和可回滚记录；
2. 将草地风强度、交互半径、RT 分辨率和实例密度整理为数据资产或 Material Instance 参数；
3. 增加首帧/后台视口截图的可靠性检测，避免将截图超时误判为功能失败；
4. 如果要支持多人或远程 AI 协作，先设计认证、TLS、审计日志和操作审批，不能直接开放当前 localhost 接口；
5. 在打包前对 Editor-only 模块和演示专用资产进行一次目标平台专项审查。
